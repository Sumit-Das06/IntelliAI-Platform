## Objectives (as set at opening)

Decide which open foundation models IntelliAI builds upon for the next
several years; make the wrapper-to-model-company trajectory explicit and
architecturally enforceable; do it before M2 pours concrete around any
model assumption. All three achieved.

## What was built

A strategy layer with teeth: every future milestone now answers to a
constitution (charter + four domain constitutions), a capability map
with an admission test, a model-identity system Registry V2 will
implement, and per-capability model recommendations whose licenses were
**verified at source on 2026-07-31** — not assumed from reputation.

## Research conclusions (headlines)

1. **Piper is unusable** (archived upstream; GPL-3.0 successor fork;
   maintainer vacancy) → **M3 TTS engine is now Kokoro-82M**; ownership/
   cloning lineage is Chatterbox (MIT); Indic wedge lineage is IndicF5
   (MIT). This single finding justified the milestone.
2. **Whisper remains the right STT lineage** — not because it leads 2026
   leaderboards (it doesn't; the top ten sit within ~1 WER point) but
   because MIT + 99 languages + the largest fine-tuning ecosystem in ASR
   is what a model company buys. M2 proceeds unchanged.
3. **One Apache family (Qwen) can back seven capabilities** — adopted
   with an explicit concentration-risk protocol (warm non-Qwen backups
   in the registry, watch triggers, pinned imports).
4. **Licenses move mid-family, in both directions** → license verdicts
   attach to artifact *versions*, never families — now an architecture
   invariant and a Registry V2 hard requirement.
5. **No commercially usable open native speech-translation model
   exists** → the composite-first design is validated by the license
   landscape, not just by architecture taste.
6. **The "open model" leaderboard is a licensing minefield** — nine
   category leaders rejected on verified license grounds (NC, revenue
   caps, unverifiable terms).

## Architecture changes

- **ADR-0015** supersedes ADR-0004: hardware-agnostic architecture,
  CPU-first *deployment posture*; all ADR-0004 mechanics carried
  forward; model selection may never veto on hardware.
- **Model identity** (two-axis hierarchy; artifacts/builds/deployments;
  data-vs-determinism bright line; multi-capability artifacts;
  `evaluation_candidate` stage) and **Registry V2** (record/resolution
  planes, intent-vs-observation, 14 laws) adopted as the conceptual
  base for Registry V1 (M2 seed) and V2 (M9).
- **Operating principles** added to the PRD: evaluation seed from M2;
  customer discovery as a parallel company activity; documentation
  governor.
- `services/tts-piper` → `services/tts-kokoro`; repository version →
  0.2.0.

## Lessons learned

1. **Research before building pays cash** — the Piper discovery cost a
   research sweep; discovering it in M3 would have cost a built service.
2. **Verify licenses at the source, always** — a third of "open" search
   results were commercially unusable; several carried permissive badges
   contradicted by their own cards (MonkeyOCR).
3. **Strategy debt compounds like code debt** — the M0-era "CPU-first"
   phrasing had quietly begun constraining model strategy; catching
   frame-drift is what milestone reviews are for.
4. **A ten-deliverable documentation milestone is at the edge of the
   documentation governor** it itself introduced — it passes only
   because M2 directly consumes its outputs. No second documentation
   milestone is planned, ever.
5. **Single-author review is the stack's weakest link** — gates were
   real, reviewers were not independent. Pre-committed mitigation: first
   ML hire red-teams the stack; external diligence welcomed.

## Risks accepted (knowingly)

- **Wedge is hypothesis-grade** until discovery + eval baselines exist
  (mitigation: both start alongside M2).
- **Qwen concentration** (mitigation: §14 protocol; Apache
  irrevocability caps downside).
- **Bounded registry staleness** and **solo-operator ceremony cost**
  (recorded in REGISTRY_V2 §15 for implementation time).
- **Research decay** — every dated verdict ages from 2026-07-31;
  re-verification is a standing adoption-time gate.
