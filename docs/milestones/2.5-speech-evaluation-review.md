## 1. The architecture, in one picture

```
Corpus → Generator → Judge → Metrics → Evidence
(immutable) (Protocol) (Protocol,   (registry-  (immutable ledger;
                        self-       declared    reports are derived,
                        identified) specs)      regenerable artifacts)
```

Capability-independent by design: the framework belongs to IntelliAI,
not to TTS — future capabilities swap the domain implementations and
keep the shape. Evaluation grows by **adding** evaluators and metric
families beside old ones, never replacing them, so historical evidence
stays interpretable forever. Evidence and reporting are formally
distinct: records are immutable and irreplaceable; reports are
presentation, always regenerable from the ledger. Baselines are company
assets — every future model must answer *"what baseline did it beat?"*

## 2. Retrospective

**What assumptions were validated?**
Evaluation-first is buildable with zero models (the entire pipeline runs
and is tested against deterministic fakes); the two-Protocol seam is
sufficient (judge-swap test passes with no runner changes); evidence
laws are enforceable in types, not just prose; failures can be preserved
with graduated honesty.

**What assumptions remain unvalidated?**
No real synthesis engine has ever flowed through the loop (n=0 — M3's
first task); the judge has never transcribed *synthetic* speech (its
error profile there is unknown); the corpus's statistical power is
seed-grade; the listening protocol has never been executed.

**What surprised us?**
Our own review found an aggregation inconsistency between the two
ledgers (mean-of-case-WERs vs the STT ledger's word-weighting) — fixed
at close (C1) inside the legal pre-citation window; `str.isalnum()`
silently destroys Devanagari matras (combining marks) — the Unicode
normalization exists because of it; a full-scale sine barely "clips"
while an overdriven one pins >30% — loud and broken are different
measurables; the benchmark's own percentile function had a truncation
bug caught by its unit test — rulers need tests too.

**What will Milestone 3 inherit?**
A complete evaluation pipeline needing exactly one ~30-line HTTP
synthesis adapter plus the deferred CLI; a ready judge (`HttpSttJudge`);
corpus v1 with hard-by-design cases pre-tagged; the conditions ledger
(§4) as gates; and the obligation to produce Kokoro's day-one baseline
and the first listening-protocol run before any promotion language is
used.

## 3. Definition of Done (final)

✓ **Evaluation-first discipline exists** — the full pipeline predates any
TTS model, tested end-to-end with fakes.
✓ **Capability-independent architecture** — Corpus→Generator→Judge→
Metrics→Evidence, stated in the methodology; engine names absent from
framework code.
✓ **Evidence/report separation** — documented as law; records immutable,
reports derived.
✓ **Deterministic baseline generation** — identical-evidence test
(modulo wall clock); manifest ordering; pinned params/judge; declared
per-metric aggregation.
✓ **Reusable evaluation pipeline** — two Protocols, adapters
interchangeable in tests; runner gains zero lines for M3.
✓ **Future evaluator expansion without redesign** — judges carry their
own identity; metric specs append; additivity is the written rule.
